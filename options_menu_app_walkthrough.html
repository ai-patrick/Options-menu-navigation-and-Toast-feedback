4.2 onCreate() — Setup & Button Wiring

Inflates the main layout, applies window insets, and wires the fault demo button.

4.3 onCreateOptionsMenu() — Inflate Menu

Called once when the menu is first created. Inflates the XML menu resource into the provided Menu object.

4.4 onOptionsItemSelected() — Route Selections

Handles each menu item by ID. Uses stable IDs (not labels) for reliable matching. Returns true when handled, false to propagate.

💡 Why use item ID instead of label? IDs are stable constants generated at compile time. Labels can change (localization, typos, redesign) and are not unique. Comparing labels is fragile and breaks with translation.

4.5 Handler Methods — Toast + Action

Each handler shows a Toast (brief feedback) then performs its specific action.

⚠️ When is Toast unsuitable? Toast is for brief, non-critical messages that auto-dismiss. Unsuitable for: validation errors (user must act), unsaved-work warnings (must persist), critical alerts (need acknowledgment), or any message requiring user response. Use AlertDialog, Snackbar with action, or inline errors instead.

5 · Event Flow Explanation

How a menu action reaches its handler and how Back returns the user safely:

  1. User taps toolbar overflow (⋮) → onCreateOptionsMenu() inflates menu if needed → menu displays
  2. User selects "View Records" → System calls onOptionsItemSelected(item) with the selected MenuItem
  3. ID matching → item.getItemId() == R.id.action_view_records matches → handleViewRecords() called
  4. Toast shown → Toast.makeText(...).show() posts brief message to UI thread
  5. Navigation → new Intent(this, ViewRecordsActivity.class) + startActivity() → new Activity starts
  6. Back pressed → ViewRecordsActivity.finish() (default) → returns to MainActivity.onResume() without re-executing the menu handler

💡 What prevents duplicate action on Back/rotation? The menu handler runs only on selection, not on Activity recreation. onCreateOptionsMenu() re-inflates the menu but doesn't trigger handlers. onOptionsItemSelected() is only called when the user actively taps an item. Rotation recreates the Activity but doesn't simulate a menu tap.

7 · Fault Diagnosis Record

PhaseDetails
Deliberate FaultIn onOptionsItemSelected(), use R.id.action_view_record (singular) instead of R.id.action_view_records (plural)
Observed SymptomSelecting "View Records" does nothing — no Toast, no navigation, no error
CauseID mismatch: menu resource defines @+id/action_view_records but handler checks for action_view_record. The else branch logs a warning and calls super.
CorrectionChange handler condition to itemId == R.id.action_view_records (exact match)
RetestSelect "View Records" → Toast appears → ViewRecordsActivity opens → Back returns cleanly
PreventionUse IDE auto-complete for IDs; write tests that invoke handlers directly; code review for ID consistency

8 · Conclusion

💡 Summary. This app demonstrates the complete Options Menu lifecycle: resource declaration (res/menu), inflation (onCreateOptionsMenu), selection handling (onOptionsItemSelected), Toast feedback for immediate acknowledgment, AlertDialog for detailed feedback, Intent-based navigation to change visible state, and a structured fault diagnosis process. The key principles are: stable IDs over labels, Toast for non-critical feedback, AlertDialog for actionable messages, and proper Activity lifecycle handling to prevent duplicate actions.

What I learned

  • Menu resources belong in res/menu/ and are inflated via MenuInflater.
  • onOptionsItemSelected() is the single dispatch point — route by item.getItemId().
  • Toast is fire-and-forget; use LENGTH_SHORT for transient, LENGTH_LONG for slightly longer.
  • Navigation with Intent + startActivity() creates a new back-stack entry; Back returns automatically.
  • Fault diagnosis: reproduce → observe symptom → identify cause (logcat, debugger) → fix → retest → document.

Possible extensions

  1. Add a "Delete Record" menu item with confirmation dialog (critical action → AlertDialog, not Toast).
  2. Persist records in Room database; populate ViewRecordsActivity from LiveData.
  3. Implement onPrepareOptionsMenu() to enable/disable items dynamically (e.g., disable "View Records" when empty).
  4. Add search to toolbar via SearchView as an action view.
